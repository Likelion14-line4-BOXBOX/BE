# 홈·채팅·마켓 표시 피드백 (2026-11-19)

## BE 수정

- `/api/home`의 `nextRace`와 현재 마켓은 운영 GET 조회에서 이미 라스베이거스(2026년 21라운드)다.
- `liveChatRoom`은 예정 채팅방 목록의 첫 항목을 사용해 아부다비를 반환했다. 목록은 종료 시각 내림차순이므로 홈 선택에는 적합하지 않았다.
- 홈은 같은 응답 기준 시각으로 LIVE를 먼저 선택하고, 없으면 가장 가까운 개장 예정 방을 선택한다. 종료·보관 방과 다른 시즌은 제외한다.
- `/api/chat-rooms`의 정렬·커서 및 모든 URL·응답 필드는 유지한다.
- 한국어 표시명 시드에서 `하스 F1 팀`을 `하스`로 정정한다. 영문 `Haas F1 Team`과 코드 `haas_f1_team`은 유지한다. 다른 사용자 지정 한국어 표기는 덮어쓰지 않는다.

## FE 담당자 전달 사항

이번 BE 변경으로 새 필드나 새로운 API 호출이 요구되는 계약 변경은 없다. 아래 항목은 기존 화면 연동·표시 설정이다. 이 작업에서 FE 파일을 수정하지 않았다.

### 홈·채팅 경기명

- `src/pages/Home/useHomeData.js`는 `VITE_HOME_API_ENABLED === "true"`일 때 API를 사용한다. 그렇지 않으면 `Home.jsx`의 멕시코시티 목업이 표시된다.
- `src/pages/TeamRadio/useRadioChat.js`는 `VITE_TEAM_RADIO_CHAT_API_ENABLED === "true"`일 때 실제 방을 사용한다. 기존 `radioData.js`와 `useChatPreview.js`의 멕시코시티 목업·미리보기와 구분한다.
- 배포 설정과 실제 네트워크 응답을 확인하고 API 경로를 활성화한다. 빌드 시 환경변수 변경은 FE 재빌드가 필요하다.
- 홈 경기명은 `GET /api/home`의 `nextRace.name`, 채팅 미리보기는 `liveChatRoom`, 실제 방은 `GET /api/chat-rooms/{roomId}`의 `raceName`을 사용한다.
- 전체 방 목록은 내림차순이므로 첫 항목을 현재 방으로 간주하지 않는다. 현재 마켓 연결 방은 `GET /api/market/rounds/current`의 `round.chatRoomId`로 식별할 수 있다.
- 라스베이거스 방은 11월 20일 08:30(KST) 개장 예정이다. 경기명 변경을 위해 LIVE로 강제하거나 운영 시각을 당기지 않는다.

### 이번 라운드 거래가 그래프

- `src/pages/RaceMarket/RaceMarketBuySell.jsx`의 `PriceChart`는 `min~max`를 Y좌표 40~8에 항상 맞춘다. 작은 가격 차이도 그래프 높이 전체로 확대된다.
- 실제 거래가·OHLC를 시각 효과 때문에 바꾸면 주문·보유 평가액·가격 이력의 의미가 달라진다. BE 가격과 기존 데모 OHLC는 유지한다.
- FE에서 시작가 기준 최소 ±1% 정도의 표시 범위를 확보하고, 실제 변동이 더 크면 실제 min/max에 여백을 더해 범위를 확장하는 방식을 제안한다. 최소 범위와 여백은 화면에서 최종 조정한다.
- 데이터 필터링이나 이동평균 없이 원래 포인트와 처음·마지막 가격을 유지한다. 수평인 데이터·급등락·가격 0 방어도 함께 확인한다.

### 닉네임과 채팅 기록

- 기존 `boxbox1~10` 데모 프로필의 표시 닉네임을 첨부에 나온 자연스러운 별명으로 정리한다. 계정 아이디·비밀번호·보유/거래·랭킹 금액은 유지한다.
- `/api/rankings`의 `items[].user.nickname`을 사용한다. DB 참조이므로 게시판·프로필·채팅에도 동일한 닉네임이 나타난다.
- 첨부의 34개 본문과 15명 작성자 구분을 유지해 지난 멕시코시티 방(19)에 넣는다. 부족한 5명은 별도 DEMO 프로필이며 새 계정의 초기 지갑과 원장을 함께 만든다.
- 첨부의 가상 ID는 운영 ID로 변환한다. `나`는 `boxbox5`의 `피트레인산책`으로 연결하며, 삭제 가능 여부는 접속 회원에 따라 서버가 계산한다. 미지원 예시 아바타는 `avatar_default`를 사용한다.
- 원본의 본선 시각이 예선보다 앞서므로 세션별 대화 순서를 유지하고 저장된 멕시코시티 세션 일정 안으로 시각을 옮긴다. 실제 시청·실제 발언 시각을 증명하는 자료가 아닌 시연용 합성 이력이다.
- 세션 구분선 5개는 `[데모]`로 표시한 별도 기록이다. 실제 세션 시작/종료 값은 수정하지 않는다. 새 기록 때문에 도장을 자동 지급하지 않으며 기존 도장은 보존한다.
- 시연용 스트림 이벤트 보존 기간은 입력 후 8일이며 메시지 본문은 논리 삭제 전까지 남는다. 이벤트 정리 후에는 해당 데모 구분선이 사라질 수 있다.

## 반영 구분

- 운영 데이터 입력과 BE 앱 배포는 별개다. 운영 데이터 보완은 조회에서 바로 확인할 수 있고, 홈의 방 선택 코드 수정은 이 브랜치의 배포가 필요하다.
- FE 화면의 실제 목업 활성화 여부와 그래프 모양은 BE HTTP 검증만으로 완료를 판단할 수 없다. FE 담당자의 배포 설정·화면 검증이 남는다.
- 운영 데이터 적용·검증 결과와 실제 커밋은 작업 루트 `ai-notes/implementation-status.md`에서 관리한다.
